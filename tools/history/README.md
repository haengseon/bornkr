# 한국 주요 사건 수집기 (1950~2025)

Node.js 22 이상. 별도 패키지, API 키, 유료 서비스, LLM 호출 없이 한 번 실행하고 종료한다.

```powershell
node tools/collect-korean-events.mjs
node tools/collect-korean-events.mjs --offline
node tools/collect-korean-events.mjs --refresh
node --test tests/tools/history.test.mjs
```

기본 결과는 `docs/research/news/`. `--out docs/research/다른폴더`로 변경할 수 있다.
첫 실행은 인터넷 연결이 필요하다. 기본 실행은 기존 응답 캐시를 재사용한다. `--offline`은 모든 필요한 캐시가 있어야 하며, 없거나 해시가 다르면 실패한다. `--refresh`는 새 응답으로 갱신한다. 응답은 45초 제한, 최대 3회 재시도, 요청 사이 최소 250ms 대기. 소스 실패는 `validation.json.failures`에 남기고 종료 코드 2를 반환한다. 기존 프로젝트의 `docs/` 제외 규칙을 따른 로컬 연구 자료이며 사이트 빌드에 자동 포함되지 않는다.

## 결과

- `events.json`: UTF-8, 한 줄 JSON 배열. 사건 묶음당 한 행. 날짜는 발행일이 아닌 사건일이다. 제목과 날짜, 분야, 출처 URL, 검증 방식, 라이선스 상태, 안정적인 ID와 topic을 보존한다. 상세 기사나 기사 요약은 복제하지 않는다.
- `validation.json`: 연도별 후보/채택/5건 대비 부족 수, 제외 사유, 실패, 원응답 URL·수집 시각·SHA-256, 최종 파일 해시.
- `sources.json`: 출처 범위, 이용 조건과 정책 URL.
- `.cache/*.json.gz`: 원응답과 URL·시각·해시. 오프라인 재현용이며 최종 배포 데이터가 아니다.

`milestones`가 있으면 같은 연도의 관련 사건을 하나로 묶은 것이다. 대표 행의 `date`는 대표 사건 날짜이며 첫 발생일이나 전체 지속 기간이 아니다. 같은 `topic`이 여러 해에 등장할 수 있다. 예를 들어 한국전쟁은 연도별 묶음으로 기록하고 동일 topic으로 연결한다. 묶음 내 세부 사건의 개별 URL도 보존한다.

## 출처와 검증 수준

1. 국가기록원 「연표와 기록」: 1950~2003년. 2003년은 2월까지만 제공된다. HTML 표의 날짜 셀과 사건 제목 셀만 추출하며, 여러 관련 기록물이 붙어도 사건을 중복 생성하지 않는다. `official-chronology`는 공식 연표에 날짜와 제목이 실제 수록됐다는 뜻이다. 기록물 원문까지 재검증했다는 뜻은 아니다.
2. 한국어 위키백과 연도 문서: 2003~2025년 후보 탐색용. 사건 및 문화 문단의 날짜·내부 링크만 처리한다. 탄생·사망, 단순 기념일, 예정 항목을 제외한다. 국내 관련 문자열과 사건명 규칙을 통과한 연도당 최대 45개 문서만 조사한다. Wikipedia 개정 ID URL을 남긴다.
3. Wikidata: 후보 사건에 연결된 QID의 P585(시점) 또는 P580(시작일)가 그레고리력·일 단위 정밀도이며 연표 날짜와 정확히 일치해야 채택한다. 연/월 단위 날짜를 1월 1일 등으로 보충하지 않는다. `wikidata-wikipedia-exact-day`는 두 Wikimedia 자료의 날짜 일치이며, 서로 독립적인 1차 사료 검증은 아니다. 표제는 후보 문서명을 유지한다(Wikidata label이 일반 장소명 등으로 연결돼 사건명이 사라지는 것을 방지). 본문 요약은 저장하지 않는다.

4. Wikidata 날짜가 없거나 일치하지 않는 후보는 해당 사건 문서의 인포박스 날짜·발생일·일시·시작일·선고일자 필드와 대조한다. 문서에 각주 또는 참고문헌 표기가 있고 날짜가 정확히 일치할 때만 `wikipedia-infobox-date-with-references`로 채택한다. 이 방식은 같은 Wikipedia 안에서 문서 사이의 일치를 확인한 것이며, 각주 원문을 직접 열어 검증한 것은 아니다. 선고일은 제목에 (선고)를 붙이고 dateField로 원래 필드를 남긴다. Wikimedia 행의 표제는 Wikipedia에서 유래하므로 CC BY-SA 4.0으로 표시하며, 대조에 쓰는 Wikidata 구조화 날짜 자체는 CC0이다. 두 자료가 충돌하면 Wikidata의 일치 날짜를 우선하되, 불일치 필드 전체를 사실로 단정하지 않는다.

위키 후보의 날짜 불일치는 별도 제외한다. P580와 P585가 존재하지 않는 사건, 연표에 없는 사건은 빠질 수 있다. Wikimedia 데이터끼리 일치해도 사실 오류가 남을 수 있으며, 사건의 원인·책임·피해 규모를 검증하는 데이터가 아니다.

## 선별과 반복 이슈

dateField가 P585/P580인 행은 Wikidata 시점 또는 시작일과 대조한 것이다. 선고일·시작일 등 날짜의 의미를 구별해야 한다.

목표는 연도별 5~15건이며 현재 상한은 10개 묶음이다. 정치·안보·외교·경제/제도·재난/보건·사회/문화에서 가능한 분야별 한 건을 먼저 확보한 뒤 규칙 점수순으로 채운다. 전쟁·민주화·선거·대형 사고 등의 단어에 가중치를 준다. 날짜·제목순 동률 처리로 재현성을 유지한다.

전쟁, 4·19, 5·18, 6월 민주화, 세월호, 코로나19, 메르스, 윤석열 계엄·탄핵, 외환위기, 언론통폐합은 명시적인 주제 규칙으로 묶는다. 나머지는 QID 또는 정규화 제목 기준이다. 모든 의미상 유사 사건을 완벽히 합치는 모델은 아니다. 선별은 전국 여론의 객관적 순위가 아니며 공식 연표의 수록 편향과 키워드 편향을 갖는다. 인물 탄생·사망과 매년 반복되는 행사로 부족 수를 채우지 않는다.

검증 가능한 후보가 5건 미만이면 그대로 저장하고 `shortfall`을 표시한다. 0건은 '아무 사건도 없었다'는 뜻이 아니다. 부족한 연도는 후속 자료 조사 대상이다.

## 라이선스

- Wikidata 구조화 데이터: CC0 1.0. <https://www.wikidata.org/wiki/Wikidata:Licensing>
- Wikipedia 텍스트: CC BY-SA 4.0. 후보 문서명을 사용한 경우를 포함해 출처·개정 링크와 이 안내를 유지한다. <https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use> / <https://creativecommons.org/licenses/by-sa/4.0/>
- 국가기록원: <https://www.archives.go.kr/next/neworgan/copyrightProtection.do>. 정책은 공공누리 마크가 부착된 자료의 해당 조건을 따르도록 안내한다. 이 연표 페이지에서 개별 KOGL 유형을 확인하지 못했으므로 `rights-unconfirmed`로 표시한다. 기관 자료 전체를 CC0 또는 KOGL 제1유형으로 간주하지 않는다. 현재는 로컬 연구용으로 날짜와 짧은 사건 표제만 보존하며, 원문·사진·영상은 저장하거나 재배포하지 않는다. 공개/상업 배포 전 해당 표제·편집물의 이용 조건을 추가 확인해야 한다.

따라서 혼합 데이터 전체에 단일 오픈 라이선스를 선언하지 않는다. 출처의 이용 조건과 프로젝트 코드의 이용 조건은 별개다.
